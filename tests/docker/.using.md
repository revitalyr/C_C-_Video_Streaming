1. Запуск Unit-тестов
Используется образ videostreaming-tests:latest. Это самый быстрый способ проверить логику кода.

bash
cd /mnt/d/work/Projects/C_C++_Video_Streaming/tests/docker/
docker compose up unit-tests
Docker запустит контейнер, выполнит скрипт /app/tests/scripts/run_unit.sh и выведет результаты (Catch2).

2. Запуск интеграционных (E2E) тестов
Для этого сценария используются receiver (ваше приложение), rtp-source (ffmpeg) и analyzer (скрипты анализа). Вы собрали docker-analyzer:latest специально для анализатора.

bash
# Запуск в фоновом режиме
docker compose up -d rtp-source receiver analyzer

# Просмотр логов анализатора (он покажет метрики RTCP, jitter, loss)
docker compose logs -f analyzer
Важно: Тесты используют сеть lossy_net. Чтобы эмуляция потерь работала корректно, убедитесь, что на хосте запущен скрипт настройки сети (упомянутый в комментариях init-netem.sh), либо тесты пройдут в "идеальной" сети.

3. Stress-тестирование (IoT профиль)
Эмуляция работы на слабом железе (ограничение CPU и памяти).

bash
docker compose --profile stress up stress-iot
